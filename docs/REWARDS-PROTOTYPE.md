## Как это работает

1. Игрок проходит **рейтинговый** раунд. Он доступен только внутри Telegram, сервер проверяет подпись игрока.
2. Когда раунд завершён, сервер (`server/src/game.js` → `finishRound`) смотрит, какие очки он сам начислил за каждый вопрос. Если за вопрос с наградой набран порог, награда записывается в таблицу `player_rewards`.
   - Клиент наград не присылает. Если он пришлёт лишние поля, сервер их игнорирует.
   - Повторно завершить раунд нельзя.
   - Одна награда хранится у игрока один раз: ключ таблицы — пара «игрок + награда».
   Завершение раунда, результат в рейтинге и награды записываются **одной транзакцией** (D1 batch, `finishRoundAtomic` в `server/src/d1-store.js`).
   - Если база даст сбой на любом шаге, откатится всё. Раунд останется незавершённым, и его можно завершить ещё раз: награда не потеряется, очки не удвоятся.
   - Результат игрока записывается только если именно эта транзакция завершила раунд. При двойной отправке раунд засчитывается один раз.
   **Повторное завершение безопасно.** Если раунд уже завершён (например, запись прошла, а ответ до игры не дошёл), сервер возвращает уже сохранённый итог с пометкой `repeated: true`: счёт, лучший результат и награды этого раунда. При этом он ничего не записывает. Игра сама повторяет запрос до 3 раз (паузы 0,8 и 2 с), но только когда исход неизвестен: нет связи или ошибка сервера 5xx. Если ответа нет и после этого, игра пишет «Сервер не ответил. Результат мог быть засчитан — проверь рейтинг позже», а не «не сохранён».
3. Рейтинг (`/api/leaderboard`) отдаёт у строки поле `cosmetics: { prefix, banner }` — только если у игрока есть награды. У остальных игроков ответ прежний.
4. Игра (`js/rewards.js`) рисует префикс перед ником и анимированную сцену на фоне строки.

Без сервера, в локальном режиме, награды не выдаются и не показываются.

## Как открыть прототип на своём компьютере

Нужен Node.js 22 или новее. Проверить версию: `node --version`. Устанавливать пакеты не нужно.

1. Откройте терминал в папке `face-value-rewards`.
2. Выполните:
   ```
   node tools/dev-server.mjs --reset --demo
   ```
   - `--reset` начинает с пустой локальной базы.
   - `--demo` создаёт 5 демо-игроков. Они играют настоящие раунды через серверный код:
     - у «Виктория С.» обе награды;
     - у длинного ника — только префикс;
     - у «Марк Д.» — только баннер;
     - у двоих наград нет.
3. Откройте в браузере `http://localhost:8787` и нажмите **«Рейтинг»**.
4. Остановить: `Ctrl + C`. Если запустить снова без `--reset`, база и награды сохранятся.

Чтобы посмотреть неподвижный вариант, включите в системе «Уменьшить движение»:
- macOS: Настройки → Универсальный доступ → Дисплей;
- iPhone: Универсальный доступ → Движение.

**Что делает стенд**
- Использует тот же `server/dist/worker.js`, что вставляется в Cloudflare.
- Вместо Cloudflare D1 использует локальный файл `dev-data/face-value-dev.sqlite`. С настоящей базой не соединяется.
- Вход «как в Telegram» подписывает случайным тестовым токеном, который придумывается при каждом запуске. Это не токен бота.
- Подмена Telegram есть только в страницах, которые отдаёт стенд. Файлы игры не меняются.

## Перенос в рабочую версию (только после вашего разрешения)

Порядок такой: сначала перенос редкостей и каталога (`face-value-products`), потом эти изменения.

1. Один раз выполните в консоли D1 файл `server/migrations/0001_player_rewards.sql`. Он только добавляет таблицу: `players` и `rounds` не меняются.
2. Вставьте новый `server/dist/worker.js` в Cloudflare.
3. Опубликуйте сайт.


## Профиль, выбор оформления и LEGENDARY-вопросы

- **LEGENDARY-вопрос.** До ответа у вопроса появляются метка `LEGENDARY`, рамка и свечение в цветах его баннера, а под фото — узкая полоска (24 px) со сценой этого баннера.
  - Тема берётся только из существующей привязки «вопрос → баннер» в `js/rewards-config.js`.
  - Фото на 34 px ниже, поэтому поле ответа и кнопка остаются на прежнем месте.
  - Цена и подсказки не показываются.
- **Вкладка «Профиль»** (меню → «Профиль»):
  - превью своей строки рейтинга;
  - выбор EPIC-префикса и LEGENDARY-баннера только из полученных, плюс «Без префикса» и «Без баннера»;
  - коллекция всех 20 наград: полученные — с датой, закрытые — приглушены, с условием (вопрос и порог очков).
- **Где хранится выбор.** В новой таблице `player_cosmetics` (миграция `server/migrations/0002_player_cosmetics.sql`, только добавляет таблицу).
  - Сервер принимает выбор только из наград, которые есть у игрока в `player_rewards`.
  - Если игрок ничего не выбирал, показывается самая новая награда каждого вида, как раньше.
- **API:**
  - `GET /api/profile` → `{ rewards: [{ id, earnedAt }], selected: { prefix, banner }, custom }`;
  - `POST /api/profile/cosmetics` с `{ prefix, banner }` (id полученной награды или null) → профиль. На невыданную награду сервер отвечает 403, на неизвестную или не того вида — 400.
- **Уведомление о награде.** После раунда, если сервер выдал награды: редкость, название, превью и кнопка «В профиль». При повторе после потерянного ответа сервер возвращает те же награды этого раунда, не выдавая их заново.
- **Локальная проверка:**
  - `node tools/dev-server.mjs --reset --reward-pool legendary` — раунды только из LEGENDARY-вопросов;
  - `--reward-pool` — из всех 20 вопросов с наградами;
  - `node tests/browser/profile.browser.mjs` — автоматическая проверка в браузере.
- **Перенос в рабочую версию** (только после разрешения): миграции 0001 и 0002 по порядку, затем `worker.js` и сайт.

# Сервер FACE VALUE: рейтинг + Telegram-бот

> **Как опубликовать через веб-панель Cloudflare, без терминала:** см. [DEPLOY.md](DEPLOY.md).

Сервер написан и проверен тестами, но **в интернете он ещё не запущен**. Ниже описано, как он устроен и как его запустить, когда вы будете готовы.

## Почему нужен сервер

Если игра хранит результат на телефоне, его можно подделать: исправить localStorage или отправить любое число. Поэтому общий рейтинг считается только на сервере.

- Игрок в Telegram открывает игру, и Telegram передаёт приложению подписанную строку `initData`.
- Приложение отправляет её на сервер в заголовке `Authorization: tma <initData>`.
- Сервер проверяет подпись своим секретным `BOT_TOKEN`. Номер пользователя (`user_id`), присланный приложением отдельно, сервер не принимает.
- Вопросы раунда выбирает сервер. Цену вопроса он сообщает только после ответа на этот вопрос, а очки считает сам, по `js/scoring.js`.

## Выбранный стек

**Cloudflare Workers + Cloudflare D1 (SQLite)**, бесплатный тариф. Карта для старта не нужна.

- Workers: до 100 000 запросов в день бесплатно.
- D1: до 5 ГБ данных и миллионы чтений в день бесплатно.
- HTTPS и домен вида `*.workers.dev` дают сразу.
- Холодного старта почти нет, сервер не «засыпает», как бесплатные Render или Heroku.

Ограничения бесплатного тарифа: лимиты запросов в день, время работы одного запроса около 10 мс CPU (для этой игры с запасом). Актуальные лимиты лучше проверить на cloudflare.com перед запуском.

## Защита от подделки

| Угроза | Защита |
|---|---|
| Чужой `user_id` | Сервер проверяет подпись `initData` (HMAC-SHA256 с ключом от `BOT_TOKEN`) |
| Старая или украденная `initData` | Отклоняется, если она старше 24 часов (`INIT_DATA_MAX_AGE`) |
| Своя сумма очков | Клиент присылает только цену-догадку, очки считает сервер |
| Подсмотреть цену в коде | Публичная сборка без цен (`tools/build-public.mjs`), цена приходит после ответа |
| Ответить дважды или параллельно | Ответ принимается по порядку и один раз (условие `answers_count = ?` в UPDATE) |
| Повторно отправить завершение раунда | Раунд завершается один раз (`status = 'active'` в UPDATE) |
| Чужой раунд | Раунд привязан к `user_id` |
| Долгий перебор | Раунд живёт 30 минут, не больше 60 раундов в час |
| Токен в коде | `BOT_TOKEN` хранится только в секретах Cloudflare (`wrangler secret put`) |

## Telegram-бот: команда /start

Telegram присылает сообщения боту на адрес `POST /telegram/webhook`. В ответ на `/start` сервер отправляет приветствие и кнопку «Играть» (`web_app`), которая открывает `WEBAPP_URL`.

- **Проверка, что запрос от Telegram.** Каждый запрос должен содержать заголовок `X-Telegram-Bot-Api-Secret-Token`, равный секрету `WEBHOOK_SECRET`. Иначе сервер отвечает 403 и ничего не отправляет.
- **Ответ без токена.** Ответ отправляется прямо в теле ответа на webhook, поэтому токен бота для `/start` не используется.
- **Подключение webhook.** Его подключают один раз, открыв `GET /telegram/setup?key=<WEBHOOK_SECRET>`. Сервер сам вызывает `setWebhook` со своим `BOT_TOKEN` и секретом, так что токен не покидает Cloudflare. Отслеживаются только сообщения (`allowed_updates: ["message"]`).
- **Проверка и откат.** `GET /telegram/status?key=…` показывает, подключён ли webhook и последнюю ошибку. `GET /telegram/disable?key=…` отключает webhook.
- **Где работает.** Только в личных чатах, в группах бот молчит.
- **Какие сообщения понимает.** `/start`, `/start <параметр>`, `/play`, `/help` и любой другой текст. На всё отвечает кнопкой «Играть».

## Настройки Cloudflare

| Имя | Тип | Зачем |
|---|---|---|
| `BOT_TOKEN` | **Secret** | Проверка подписи игроков и подключение webhook |
| `WEBHOOK_SECRET` | **Secret** | Защита webhook и служебных адресов |
| `WEBAPP_URL` | Text | Адрес игры для кнопки «Играть» |
| `ALLOWED_ORIGIN` | Text | Сайт игры, которому разрешено обращаться к серверу |
| `DB` | D1 binding | База рейтинга |

`GET /api/health` показывает, что из этого настроено (true/false). Сами значения секретов он не показывает.

## Тесты

```
cd server
node --test test/*.test.js
```

Нужен Node.js 22+: тест базы использует встроенный `node:sqlite`. Тесты проверяют:

- подпись Telegram и подделку подписи;
- бота: ответ на `/start` с кнопкой «Играть», отказ без секрета webhook, служебные адреса setup/status/disable, отсутствие токена в ответах;
- собранный файл `dist/worker.js`: один файл, без внешних импортов и секретов, `/start` и рейтинг работают;
- просроченные сессии;
- двойные и параллельные ответы, повторное завершение раунда, чужие раунды;
- просрочку раунда и лимит раундов в час;
- рейтинг и HTTP-ответы;
- те же SQL-запросы, что и в D1, на настоящем SQLite.

## Вариант для терминала (wrangler)

Проще всего публиковать через веб-панель по [DEPLOY.md](DEPLOY.md). Терминальный вариант ниже — для тех, кому удобнее команды.

Всё бесплатно, но потребуется ваш аккаунт Cloudflare. Без вашего согласия я ничего не регистрирую.

1. Зарегистрируйтесь на dash.cloudflare.com (бесплатный тариф).
2. В папке `server` выполните команды:
   ```
   npm install
   npx wrangler login
   npx wrangler d1 create face-value
   ```
   Последняя команда напечатает `database_id`. Вставьте его в `wrangler.toml`.
3. Создайте таблицы:
   ```
   npx wrangler d1 execute face-value --remote --file=schema.sql
   ```
4. Добавьте токен бота (его выдаёт @BotFather). Токен вводится в терминале и не попадает в код:
   ```
   npx wrangler secret put BOT_TOKEN
   npx wrangler secret put WEBHOOK_SECRET
   ```
5. Опубликуйте сервер:
   ```
   npx wrangler deploy
   ```
   Wrangler покажет адрес вида `https://face-value-api.<имя>.workers.dev`.
6. Проверьте, что сервер жив: откройте `https://.../api/health`. Должно быть `{"ok":true,...}`.
7. В корне проекта соберите публичную версию и опубликуйте папку `dist/`:
   ```
   node tools/build-public.mjs --api https://face-value-api.<имя>.workers.dev
   ```
8. В `wrangler.toml` замените `ALLOWED_ORIGIN = "*"` на адрес, с которого открывается игра, и снова выполните `npx wrangler deploy`.

Локально запустить сервер можно командой `npx wrangler dev`. Перед этим скопируйте `.dev.vars.example` в `.dev.vars`.

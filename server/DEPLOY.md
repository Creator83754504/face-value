# Публикация сервера и бота через веб-панель Cloudflare

Эта инструкция для новичка: терминал не нужен, всё делается в браузере. Бесплатного тарифа Cloudflare хватает.

**Что получится в итоге**

- На команду `/start` бот @FaceValueGameBot отвечает приветствием и кнопкой «Играть», которая открывает игру.
- На том же сервере работает рейтинг игроков.

**Что понадобится**

- Файл `server/dist/worker.js` из проекта. Это весь сервер, собранный в один файл.
- Файл `server/schema.sql` — таблицы базы данных.
- Токен бота из @BotFather.
- Примерно 20–30 минут.

> Названия кнопок в панели Cloudflare иногда меняются. Если пункт называется чуть иначе, ищите похожий по смыслу.

---

## Правила безопасности (прочитайте один раз)

1. **Токен бота** — это пароль от бота. Вводите его только в одном месте: в настройках Cloudflare, как **Secret** (шаг 4). Не вставляйте токен в код, на GitHub, в README и в чаты, в том числе в чат со мной.
2. Если токен всё же где-то засветился, сразу отправьте в @BotFather команду `/revoke` и выберите бота. Старый токен перестанет работать. Новый токен вставьте в Cloudflare вместо старого.
3. **WEBHOOK_SECRET** — второй пароль, который придумываете вы сами. По нему сервер понимает, что сообщение пришло действительно от Telegram.
   - Длина: 32–64 символа.
   - Можно использовать только латинские буквы, цифры, `_` и `-`.
   - Пример формата (не используйте его): `fv_Q8m2Lx7RpT4vZs9Kc1Ny6Hb3Wd5Ja0Ge`.
   - Удобнее всего попросить менеджер паролей (Google, Apple, 1Password) сгенерировать пароль без спецсимволов.
   - Сохраните его в заметках: он понадобится на шагах 4 и 6.
4. В файле `dist/worker.js` секретов нет. Его можно спокойно хранить на GitHub.

## Шаг 1. Аккаунт Cloudflare

1. Откройте https://dash.cloudflare.com/sign-up.
2. Зарегистрируйтесь по e-mail и подтвердите почту. Тариф — **Free**, банковская карта не нужна.

## Шаг 2. База данных для рейтинга

1. В левом меню откройте **Storage & Databases → D1 SQL Database**.
2. Нажмите **Create Database**, введите имя `face-value` и нажмите **Create**.
3. Откройте созданную базу и перейдите на вкладку **Console**.
4. Откройте на компьютере файл `server/schema.sql` в обычном текстовом редакторе: Блокнот на Windows или TextEdit на Mac.
5. Скопируйте всё содержимое, вставьте в поле консоли и нажмите **Execute**.
6. Проверка: на вкладке **Tables** должны появиться таблицы `players` и `rounds`.

## Шаг 3. Создать Worker и вставить код

1. В левом меню откройте **Compute (Workers) → Workers & Pages**.
2. Нажмите **Create**, затем вкладку **Workers** и вариант **Start with Hello World!**
3. В поле имени введите `face-value-api` и нажмите **Deploy**.
   - Cloudflare покажет адрес вида `https://face-value-api.<ваше-имя>.workers.dev`. Сохраните его.
4. Нажмите **Edit code**. Слева откроется файл `worker.js` с примером.
5. Удалите весь пример: `Ctrl + A`, затем `Delete`. На Mac: `Cmd + A`, затем `Delete`.
6. Откройте у себя файл `server/dist/worker.js` в текстовом редакторе, скопируйте всё содержимое и вставьте в редактор Cloudflare.
7. Нажмите **Deploy** в правом верхнем углу.

## Шаг 4. Настройки и секреты

Откройте Worker `face-value-api`, затем **Settings → Variables and Secrets** и нажимайте **+ Add** для каждой строки:

| Тип | Имя | Значение |
|---|---|---|
| Text | `WEBAPP_URL` | `https://creator83754504.github.io/face-value/` |
| Text | `ALLOWED_ORIGIN` | `https://creator83754504.github.io` |
| **Secret** | `BOT_TOKEN` | токен из @BotFather |
| **Secret** | `WEBHOOK_SECRET` | ваш придуманный секрет |

Для `BOT_TOKEN` и `WEBHOOK_SECRET` обязательно выберите тип **Secret**. Тогда значение нельзя будет посмотреть даже вам. После добавления всех строк нажмите **Deploy**.

## Шаг 5. Подключить базу к Worker

1. В том же Worker откройте **Settings → Bindings**.
2. Нажмите **+ Add**, выберите **D1 database**.
3. В поле **Variable name** введите `DB` — ровно так, заглавными буквами.
4. В поле **D1 database** выберите `face-value`.
5. Нажмите **Add Binding** или **Deploy**.

## Шаг 6. Проверить сервер и подключить бота

1. Откройте в браузере `https://face-value-api.<ваше-имя>.workers.dev/api/health`. Должно получиться примерно так:
   ```json
   {"ok":true,"questions":100,"database":true,"botToken":true,"webhookSecret":true,"webAppUrl":"https://creator83754504.github.io/face-value/"}
   ```
   Если где-то `false`, вернитесь к шагу 4 или 5.
2. **Подключите webhook**, то есть скажите Telegram, куда отправлять сообщения боту. Откройте адрес, подставив ваш адрес Worker и ваш секрет:
   ```
   https://face-value-api.<ваше-имя>.workers.dev/telegram/setup?key=<WEBHOOK_SECRET>
   ```
   Ответ должен быть `{"ok":true, "webhook":".../telegram/webhook", "telegram":"Webhook was set"}`. Токен в этот момент не покидает Cloudflare: сервер сам обращается к Telegram.
3. Проверьте состояние:
   ```
   https://face-value-api.<ваше-имя>.workers.dev/telegram/status?key=<WEBHOOK_SECRET>
   ```
   Ожидается `"connected": true` и `"last_error": null`.
4. Откройте чат с @FaceValueGameBot и отправьте `/start`. Должно прийти приветствие и кнопка **«Играть»**. Нажмите её — откроется игра.

## Если что-то пошло не так

| Признак | Что сделать |
|---|---|
| `/start` молчит | Откройте `/telegram/status?key=…` и посмотрите `last_error` |
| `last_error: Wrong response from the webhook: 403` | `WEBHOOK_SECRET` в Cloudflare и в webhook отличаются. Откройте `/telegram/setup?key=…` ещё раз |
| `last_error: … 503` | Не задан `WEBHOOK_SECRET` или `WEBAPP_URL` (шаг 4) |
| `/telegram/setup` отвечает `forbidden` | В адресе неверный `key` |
| `/telegram/setup` отвечает `Unauthorized` от Telegram | Неверный `BOT_TOKEN`. Замените секрет на шаге 4 |
| Кнопка открывает не ту страницу | Проверьте `WEBAPP_URL` |
| Нужно всё откатить | Откройте `/telegram/disable?key=…`. Бот снова замолчит, а игра продолжит открываться через кнопку меню |

Логи сервера: Worker → **Logs** (Observability) → включите **Real-time logs** и отправьте боту `/start`.

## Что это не меняет

- Кнопку меню и настройки Mini App в @BotFather трогать не нужно. Webhook с ними не конфликтует.
- Игра на GitHub Pages продолжит работать как сейчас.
- Общий рейтинг в игре включится отдельным шагом. Для этого в `js/config.js` нужно указать адрес Worker в `API_BASE` (см. `server/README.md`). До этого игра работает в локальном режиме.

## Как обновлять сервер

1. Если код в `server/src` изменился, пересоберите файл: `npm install`, затем `npm run build` в папке `server`. Или попросите меня собрать его.
2. Снова выполните шаг 3, пункты 4–7: вставьте новый `dist/worker.js` и нажмите **Deploy**.

Секреты и привязка базы при этом сохраняются.
